## 1. Executive Summary

### 1.1 What We're Building

A **Cache Store Explorer UI** — a new page within the MGraph HTML Graph Render UI that allows users to:

1. **Browse** the hierarchical cache structure (sites → domains → pages)
2. **View** cached HTML content
3. **Edit** and save HTML back to the cache
4. **Inspect** FLeT flow execution logs and timing data (Jaeger-style visualization)
5. **Preview** cached pages in an embedded mini-browser

### 1.2 Why We're Building It

The HTML Store & Retrieval system (FLeT HTML Domain) is a powerful caching layer, but currently has **no visual interface**. Developers and operators need to:

| Need | Current State | With v0.2.11 |
|------|---------------|--------------|
| See what's cached | Manual API calls or filesystem inspection | Visual tree browser |
| Debug cache issues | Read raw JSON logs | Timeline visualization |
| Edit cached content | No UI — requires direct API calls | In-browser editor |
| Understand performance | Parse duration data manually | Jaeger-style flow timeline |
| Preview cached pages | Load HTML manually | Embedded iframe preview |

### 1.3 Key Design Decisions

| Decision | Rationale |
|----------|-----------|
| **Path-based navigation** (not full listing) | API doesn't support full entity listing for scalability. We drill down via `/entities/by-path/{prefix}` |
| **Namespace as first-class concept** | All operations are namespace-scoped. UI must make namespace selection prominent |
| **Read-then-write for edits** | No dedicated "update" endpoint at domain level. We load HTML, edit, then re-store with same key |
| **Lazy loading of flow data** | Flow logs/tasks/durations fetched on-demand, not pre-loaded |
| **Standalone page** (not integrated into playground) | Different use case — cache management vs. graph visualization |

### 2.2 API Endpoints Used

| Endpoint | Method | Purpose |
|----------|--------|---------|
| `/cache-entity/{ns}/entities/by-path/{prefix}` | GET | Browse folder structure |
| `/flet-html-domain/html/load/{ns}/key/{key}` | POST | Load HTML by cache key |
| `/flet-html-domain/html/store/{ns}/key/{key}` | POST | Store/update HTML |
| `/flet-flows/flows/{ns}/{cache_id}` | GET | List flows for entity |
| `/flet-flows/flows/{ns}/{cache_id}/{flet}/logs` | GET | Get flow logs |
| `/flet-flows/flows/{ns}/{cache_id}/{flet}/tasks` | GET | Get task breakdown |
| `/flet-flows/flows/{ns}/{cache_id}/{flet}/durations` | GET | Get timing data |

### 6.3 API Client Extensions (Surgical Override)

```javascript
// v0.2.11/js/services/api-client.js

/**
 * Get folders under a path prefix
 * @param {string} namespace
 * @param {string} pathPrefix
 * @returns {Promise<{folders: string[], count: number}>}
 */
ApiClient.prototype.listFoldersByPath = async function(namespace, pathPrefix = '') {
    return this.get(`/cache-entity/${namespace}/entities/by-path/${pathPrefix}`);
};

/**
 * Load HTML by cache key
 * @param {string} namespace
 * @param {string} cacheKey
 * @returns {Promise<{html: string, cache_id: string, cache_hash: string, ...}>}
 */
ApiClient.prototype.loadHtmlByKey = async function(namespace, cacheKey) {
    return this.post(`/flet-html-domain/html/load/${namespace}/key/${cacheKey}`, {});
};

/**
 * Store/update HTML by cache key
 * @param {string} namespace
 * @param {string} cacheKey
 * @param {string} html
 * @returns {Promise<{success: boolean, cache_id: string, ...}>}
 */
ApiClient.prototype.storeHtmlByKey = async function(namespace, cacheKey, html) {
    return this.post(`/flet-html-domain/html/store/${namespace}/key/${cacheKey}`, { html });
};

/**
 * List flows for an entity
 * @param {string} namespace
 * @param {string} cacheId
 * @returns {Promise<{flets: string[], count: number}>}
 */
ApiClient.prototype.listFlows = async function(namespace, cacheId) {
    return this.get(`/flet-flows/flows/${namespace}/${cacheId}`);
};

/**
 * Get flow durations
 */
ApiClient.prototype.getFlowDurations = async function(namespace, cacheId, fletName) {
    return this.get(`/flet-flows/flows/${namespace}/${cacheId}/${fletName}/durations`);
};

/**
```

## 9. Summary

We're building a **Cache Store Explorer UI** that transforms the HTML caching system from an API-only service into a visual, interactive tool. This enables:

1. **Developers**: Debug cache issues, inspect stored HTML, understand flow performance
2. **Operators**: Monitor cache contents, identify large entries, track usage patterns
3. **Content Teams**: View and edit cached content without API knowledge

The implementation follows **IFD methodology**:
- Web Components for encapsulation
- Event-driven communication
- Surgical overrides for incremental development
- Real API data from day one (no mocks)
