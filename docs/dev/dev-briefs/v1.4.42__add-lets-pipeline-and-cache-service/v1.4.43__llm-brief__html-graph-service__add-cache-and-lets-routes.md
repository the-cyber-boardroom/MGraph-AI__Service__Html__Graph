# LLM Implementation Brief: Add Cache and Lets API Routes to HTML Graph Service  

## Overview

Implement REST API routes for the `mgraph_ai_service_html_graph` service to expose LETS pipeline execution, profile management, and cache document operations. These routes enable external callers (including the HTML Graph UI) to execute HTML transformations and manage cached results.

---

## Context

### What is LETS?

LETS (Layered Extraction and Transformation System) is a pipeline framework for transforming HTML through discrete steps:

- **Step**: A single transformation unit (e.g., `html-to-dict`, `html-from-raw`, `dict-to-mgraph`)
- **Profile**: A predefined chain of steps (e.g., `html-to-mgraph` profile runs `html-from-raw` → `html-to-dict` → `dict-to-mgraph`)
- **Cache Document**: Stores HTML and all transformation outputs, keyed by semantic path (cache_key like `example.com/page`)

## Routes to Implement

### 1. LETS Steps Routes (`Routes__LETS__Steps`)

**Tag**: `lets`
**Purpose**: Discovery and execution of individual LETS steps

#### Discovery Endpoints (no namespace needed)

| Method | Path | Description |
|--------|------|-------------|
| GET | `/lets/steps` | List all available step types |
| GET | `/lets/steps/{step_type}` | Get details about a specific step |

#### Stateless Execution (no caching, no namespace)

| Method | Path | Description |
|--------|------|-------------|
| POST | `/lets/steps/{step_type}/execute` | Execute step on raw input, return result |

#### Cached Execution (requires namespace and cache_id)

| Method | Path | Description |
|--------|------|-------------|
| POST | `/lets/{namespace}/steps/{step_type}/execute/{cache_id}` | Execute step and store in cache |
| GET | `/lets/{namespace}/steps/{step_type}/status/{cache_id}` | Check if step completed for document |

---

### 2. Profile Routes (`Routes__Profiles`)

**Tag**: `profiles`
**Purpose**: Discovery and execution of predefined step chains

#### Discovery Endpoints (no namespace needed)

| Method | Path | Description |
|--------|------|-------------|
| GET | `/profiles` | List all registered profiles |
| GET | `/profiles/{profile_id}` | Get profile details (steps list) |

#### Stateless Execution (no caching, no namespace)

| Method | Path | Description |
|--------|------|-------------|
| POST | `/profiles/{profile_id}/execute` | Execute full profile on raw HTML |

#### Cached Execution (requires namespace and cache_id)

| Method | Path | Description |
|--------|------|-------------|
| POST | `/profiles/{namespace}/{profile_id}/execute/{cache_id}` | Execute profile and cache all results |

---

### 3. Cache Document Routes (`Routes__Cache__Document`)

**Tag**: `cache`
**Prefix**: `/{namespace}/cache`
**Purpose**: High-level document operations

#### Document Operations

| Method | Path | Description |
|--------|------|-------------|
| POST | `/cache/{namespace}/document/find-or-create` | Find by cache_key or create new |
| GET | `/cache/{namespace}/document/{cache_id}` | Get document metadata |
| GET | `/cache/{namespace}/document/{cache_id}/status` | Get all step completion statuses |
| DELETE | `/cache/{namespace}/document/{cache_id}` | Delete document and all layers |

#### Layer Operations

| Method | Path | Description |
|--------|------|-------------|
| GET | `/cache/{namespace}/document/{cache_id}/layers` | List all layers |
| GET | `/cache/{namespace}/document/{cache_id}/layer/{layer_name}/files` | List files in layer |
| GET | `/cache/{namespace}/document/{cache_id}/layer/{layer_name}/{file_id}` | Get file content |

    """Request for stateless step execution"""

## Implementation Order

### Phase 1: Discovery Routes (Read-Only)
1. `GET /lets/steps` - List step types from enum
2. `GET /lets/steps/{step_type}` - Step details
3. `GET /profiles` - List profiles from registry
4. `GET /profiles/{profile_id}` - Profile details

### Phase 2: Stateless Execution
1. `POST /lets/steps/{step_type}/execute` - Execute single step
2. `POST /profiles/{profile_id}/execute` - Execute profile chain

### Phase 3: Cache Document Routes
1. `POST /cache/{namespace}/document/find-or-create`
2. `GET /cache/{namespace}/document/{cache_id}`
3. `GET /cache/{namespace}/document/{cache_id}/status`
4. `DELETE /cache/{namespace}/document/{cache_id}`
5. Layer listing and file retrieval routes

### Phase 4: Cached Execution
1. `POST /lets/{namespace}/steps/{step_type}/execute/{cache_id}`
2. `GET /lets/{namespace}/steps/{step_type}/status/{cache_id}`
3. `POST /profiles/{namespace}/{profile_id}/execute/{cache_id}`

## Notes

2. **No custom profiles**: Users cannot register profiles via API - only built-in profiles
3. **Parallel to existing routes**: These routes run alongside existing `/graph/...` routes
4. **Terminology**: Use "step" (not "implementation") for LETS transformation units
