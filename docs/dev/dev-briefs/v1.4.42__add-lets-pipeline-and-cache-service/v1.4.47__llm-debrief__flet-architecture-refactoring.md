# FLeT Architecture Refactoring Debrief

**Version**: v1.4.47  
**Date**: January 2026  
**Status**: Architecture Implemented - Logic Refinement In Progress

---

## 1. Executive Summary

### What Changed

The LETS (Load-Extract-Transform-Save) framework has been renamed and refactored to **FLeT** (Flow + Load + Extract + Transform). This refactoring introduces:

1. **Cleaner naming**: FLeT emphasizes the Flow/Task foundation and makes Save optional
2. **Static action pattern**: Actions are module-level functions assigned as class attributes
3. **Modular file structure**: Separate files for schemas and actions per FLeT step
4. **Method-based base class**: Uses `NotImplementedError` instead of `Callable` for better Type_Safe compatibility

### Why FLeT?

| Old Name | New Name | Rationale |
|----------|----------|-----------|
| LETS | FLeT | "LETS" with trailing "s" was awkward |
| Load-Extract-Transform-Save | Flow+Load+Extract+Transform | Save is often optional; Flow emphasizes the execution foundation |

## 3. Static Action Pattern

### Pattern Overview

Actions are **module-level functions** decorated with `@task()` and `@type_safe`, then assigned as **class attributes** on the FLeT class:

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                        STATIC ACTION PATTERN                                 │
└─────────────────────────────────────────────────────────────────────────────┘

    actions/
    ├── action__html_to_cache__load.py
    ├── action__html_to_cache__extract.py
    ├── action__html_to_cache__transform.py
    └── action__html_to_cache__save.py

    Each file contains ONE function:
    ┌─────────────────────────────────────────────────────────────────────┐
    │  @task()                                                            │
    │  @type_safe                                                         │
    │  def action__html_to_cache__load(input_data: Schema__Load__Input    │
    │                             ) -> Schema__Load__Output:              │
    │      # Implementation                                               │
    │      return Schema__Load__Output(...)                               │
    └─────────────────────────────────────────────────────────────────────┘

    FLeT class wires them:
    ┌─────────────────────────────────────────────────────────────────────┐
    │  class FLeT__Html__To__Cache(Html_FLeT__Base):                      │
    │                                                                     │
    │      load      = action__html_to_cache__load      # Static assign   │
    │      extract   = action__html_to_cache__extract                     │
    │      transform = action__html_to_cache__transform                   │
    │      save      = action__html_to_cache__save                        │
    └─────────────────────────────────────────────────────────────────────┘
```

### Why Static Functions?

| Approach | Pros | Cons |
|----------|------|------|
| **Instance methods** | IDE completion, familiar | Must override in subclass |
| **Callable attributes** | Declarative wiring | Doesn't work well with Type_Safe |
| **Static functions (chosen)** | Reusable, testable independently, declarative wiring | Must use `cls.method()` in run_pipeline |

### Dependency Injection via run_pipeline

When actions need additional dependencies (like `cache_client`), the FLeT class overrides `run_pipeline()`:

```python
class FLeT__Html__To__Cache(Html_FLeT__Base):
    cache_client : Html_Cache__Client = None

    load      = action__html_to_cache__load
    extract   = action__html_to_cache__extract
    transform = action__html_to_cache__transform
    save      = action__html_to_cache__save

    def run_pipeline(self, input_data: Schema__Load__Input) -> Schema__Save__Output:
        cls = type(self)                                                    # Get class for static calls
        load_output      = cls.load     (input_data)
        extract_output   = cls.extract  (load_output   , cache_client=self.cache_client)
        transform_output = cls.transform(extract_output, cache_client=self.cache_client)
        save_output      = cls.save     (transform_output, cache_client=self.cache_client)
        return save_output
```

## 6. Action Implementation Pattern

### Standard Action Structure

Each action file follows this pattern:

```python
# action__html_to_cache__load.py

from mgraph_ai_service_html_graph.service.flet_pipeline.flet.steps.html__to__cache.schemas.Schema__Html_To_Cache__Load__Input  import Schema__Html_To_Cache__Load__Input
from mgraph_ai_service_html_graph.service.flet_pipeline.flet.steps.html__to__cache.schemas.Schema__Html_To_Cache__Load__Output import Schema__Html_To_Cache__Load__Output
from osbot_utils.type_safe.type_safe_core.decorators.type_safe import type_safe
from osbot_utils.helpers.flows.decorators.task                 import task


@task()
@type_safe
def action__html_to_cache__load(input_data: Schema__Html_To_Cache__Load__Input
                           ) -> Schema__Html_To_Cache__Load__Output:
    cache_key = input_data.cache_key or input_data.url or ''
    return Schema__Html_To_Cache__Load__Output(html      = input_data.html     ,
                                               namespace = input_data.namespace,
                                               cache_key = cache_key           )
```

### Actions with Dependencies

When an action needs external dependencies (like `cache_client`), add as optional parameter:

```python
@task()
@type_safe
def action__html_to_cache__transform(input_data  : Schema__Html_To_Cache__Extract__Output,
                                     cache_client: Html_Cache__Client = None              # Optional dependency
                                ) -> Schema__Html_To_Cache__Transform__Output:
    html_str   = str(input_data.html)
    char_count = len(html_str)

    if cache_client:
        html_hash = cache_client.hash_generator.from_string(html_str)
    else:
        html_hash = Safe_Str__Cache_Hash('')

    return Schema__Html_To_Cache__Transform__Output(...)
```

## 7. FLeT Class Implementation

### Complete FLeT Class Pattern

```python
# FLeT__Html__To__Cache.py

class FLeT__Html__To__Cache(Html_FLeT__Base):

    # Additional dependencies
    cache_client : Html_Cache__Client = None

    # Wire static action functions
    load      = action__html_to_cache__load
    extract   = action__html_to_cache__extract
    transform = action__html_to_cache__transform
    save      = action__html_to_cache__save

    def setup(self) -> 'FLeT__Html__To__Cache':
        self.config = Schema__FLeT__Config(
            name        = Safe_Str__FLeT__Name('html-to-cache'),
            description = 'Store HTML in cache with hash-based deduplication')
        return self

    def run_pipeline(self, input_data: Schema__Html_To_Cache__Load__Input
                ) -> Schema__Html_To_Cache__Save__Output:
        cls = type(self)
        load_output      = cls.load     (input_data)
        extract_output   = cls.extract  (load_output   , cache_client=self.cache_client)
        transform_output = cls.transform(extract_output, cache_client=self.cache_client)
        save_output      = cls.save     (transform_output, cache_client=self.cache_client)
        return save_output

    # Type-safe execute override for specific input/output types
    @type_safe
    def execute(self, input_data: Schema__Html_To_Cache__Load__Input
           ) -> Schema__Html_To_Cache__Save__Output:
        return super().execute(input_data=input_data)

    # Convenience class method
    @classmethod
    def from_html(cls, html: str, cache_client: Html_Cache__Client,
                  namespace: str = 'html-cache', cache_key: str = '', url: str = ''
             ) -> Schema__Html_To_Cache__Save__Output:
        flet = cls(cache_client=cache_client).setup()
        input_data = Schema__Html_To_Cache__Load__Input(
            html      = Safe_Str__Html(html),
            namespace = Safe_Str__Namespace(namespace),
            cache_key = cache_key,
            url       = url)
        flet.execute(input_data)
        return flet.flow.flow_return_value
```

## 10. Benefits of New Architecture

| Aspect | Benefit |
|--------|---------|
| **Testability** | Actions are pure functions, testable in isolation |
| **Reusability** | Same action can be used by multiple FLeTs |
| **Type Safety** | Full type hints on methods and functions |
| **IDE Support** | Method signatures visible, autocomplete works |
| **Modularity** | One file per action, one folder per FLeT step |
| **Flexibility** | run_pipeline can inject any dependencies |
| **Observability** | Flow/Task system captures timing and logs |
