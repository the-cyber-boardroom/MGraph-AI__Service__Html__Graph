## Data Format

All tools consume `full_*.json` files with this structure:

```json
{
  "traces": {
    "metadata": {
      "total_duration_ms": 40.73,
      "entry_count": 468,
      "method_count": 30
    },
    "call_tree": [
      {
        "name": "method_name",
        "start_ns": 1000000,
        "end_ns": 2000000,
        "duration_ms": 1.0,
        "self_ms": 0.1,
        "depth": 0,
        "call_index": 0,
        "children": [...]
      }
    ]
  }
}
```

**Important quirk:** The `call_tree` array contains root-level entries with `depth: 1` that are logically children but stored as siblings. Use `node.depth` field for indentation, not array nesting.

## Network Graph Visualizer - Architecture

### Two Data Processing Modes

| Mode | Function | Output |
|------|----------|--------|
| **Schema** | `processToSchemaGraph()` | Aggregates by method name. 30 nodes for 30 unique methods. Shows "who calls whom" |
| **Execution** | `processToExecutionGraph()` | One node per `call_index`. 234 nodes for 234 calls. Shows actual execution flow |

### Three Layout Modes

| Layout | D3 API | Use Case |
|--------|--------|----------|
| **Force** | `d3.forceSimulation()` | Interactive exploration, draggable nodes |
| **Tree** | `d3.tree()` | Top-down hierarchy visualization |
| **Radial** | `d3.tree()` + polar transform | Circular hierarchy, root at center |

### Component Architecture

```
NetworkGraphVisualizer (main)
├── State: files, selectedKey, graphMode, layoutMode, sizeBy, 
│          selectedNode, hoveredNode, fitTrigger, dimensions
│
└── GraphVisualization (React.memo wrapped)
    ├── Props: data, width, height, sizeBy, selectedNode, 
    │          onNodeClick, setHoveredNode, fitTrigger, graphMode, layoutMode
    │
    └── D3 renders into SVG ref
```

## Critical Bug Fix: Hover Infinite Loop

### The Problem
Mouse hover over nodes caused infinite re-render loop, making UI unusable.

### Root Cause
```javascript
// BAD: onNodeHover in useEffect dependencies
useEffect(() => {
  nodeSelection.on('mouseover', (event, d) => onNodeHover(d));
}, [data, ..., onNodeHover]);  // ← onNodeHover changes on every parent render
```

**Chain reaction:**
1. Hover → `setHoveredNode(node)` 
2. Parent re-renders (state changed)
3. `onNodeHover` is new function reference
4. useEffect re-runs (dependency changed)
5. D3 rebuilds entire graph
6. New nodes under mouse → triggers hover again
7. GOTO 1

### The Solution

```javascript
// GOOD: Use ref to store setter, exclude from dependencies
const GraphVisualization = React.memo(({ setHoveredNode, ... }) => {
  // Store in ref - changes don't trigger re-render
  const hoverSetterRef = useRef(setHoveredNode);
  hoverSetterRef.current = setHoveredNode;
  
  useEffect(() => {
    // Access via ref - stable reference
    const handleHover = (nodeData) => {
      hoverSetterRef.current?.(nodeData);
    };
    
    nodeSelection.on('mouseover', (event, d) => handleHover(d));
  }, [data, width, height, sizeBy, selectedNode, onNodeClick, graphMode, layoutMode, fitToView]);
  // ↑ setHoveredNode NOT in dependencies
});
```

**Why this works:**
- `React.memo` prevents re-render when only `hoveredNode` state changes in parent
- Ref stores latest setter without being a dependency
- D3 graph remains stable, only sidebar updates

function loadFrame(target) {
  const frame = document.getElementById(`frame-${target}`);
  if (frame.dataset.src && !frame.src) {
    frame.src = frame.dataset.src;  // Triggers load
  }
}

## D3 Patterns Used

### Force Layout
```javascript
const simulation = d3.forceSimulation(nodes)
  .force('link', d3.forceLink(links).id(d => d.id).distance(80))
  .force('charge', d3.forceManyBody().strength(-200))
  .force('center', d3.forceCenter(width / 2, height / 2))
  .force('collision', d3.forceCollide().radius(d => nodeRadius(d) + 3));
```

### Tree Layout (Hierarchical)
```javascript
const hierarchy = d3.hierarchy(root);
const treeLayout = d3.tree().size([width - 100, height - 100]);
treeLayout(hierarchy);
// hierarchy.descendants() for nodes, hierarchy.links() for edges
```

### Radial Layout (Polar Transform)
```javascript
const treeLayout = d3.tree()
  .size([2 * Math.PI, radius])
  .separation((a, b) => (a.parent === b.parent ? 1 : 2) / a.depth);

treeLayout(hierarchy);

hierarchy.each(d => {
  const angle = d.x;
  const r = d.y;
  d.x = r * Math.cos(angle - Math.PI / 2) + centerX;
  d.y = r * Math.sin(angle - Math.PI / 2) + centerY;
});
```

### Zoom + Pan
```javascript
const zoom = d3.zoom()
  .scaleExtent([0.05, 4])
  .on('zoom', (event) => g.attr('transform', event.transform));
svg.call(zoom);
```

### Fit to View
```javascript
const bounds = g.node().getBBox();
const scale = Math.min(
  (width - padding * 2) / bounds.width,
  (height - padding * 2) / bounds.height,
  maxScale
);
const tx = width / 2 - (bounds.x + bounds.width / 2) * scale;
const ty = height / 2 - (bounds.y + bounds.height / 2) * scale;

svg.transition().duration(300).call(
  zoom.transform,
  d3.zoomIdentity.translate(tx, ty).scale(scale)
);
```

## Known Issues / Future Work

1. **Schema mode with Tree layout** - Can have disconnected subgraphs if methods are called from multiple parents (tree assumes single parent)

2. **Large execution graphs** - 1000+ nodes may be slow; consider:
   - Canvas rendering instead of SVG
   - WebGL (e.g., force-graph library)
   - Virtualization / level-of-detail

3. **Descriptions panel** - Was commented out in index.html because hover behavior was inverted (showed when using UI, not when hovering nav). Could be fixed with proper CSS `:hover` on nav buttons instead of content area.

## Key Learnings

1. **React + D3 integration** - Keep D3 isolated in `useEffect`, use `React.memo` to prevent re-renders, store callbacks in refs

2. **Dependency array discipline** - Any function prop in dependencies will cause re-render cascade; use refs for event handlers

3. **D3 layouts are configurable** - Tree, radial, force are mostly the same code with different layout computation

4. **Fit-to-view timing** - Must wait for D3 to compute positions before calculating bounding box; use `setTimeout` or simulation `'end'` event

5. **Standalone HTML simplicity** - Babel standalone + CDN scripts = zero build step, easy deployment
