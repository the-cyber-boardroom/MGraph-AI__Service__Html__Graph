## 1. Executive Summary

### What We're Changing

This brief describes refinements to the FLeT (Flow + Load + Extract + Transform) architecture to achieve:

1. **Clean separation** between entity management (Tier 1) and data operations (Tier 2)
2. **Uniform action signatures** - all actions follow the same `input → output` pattern
3. **Single responsibility** - FLeTs can have as few as one action
4. **Data isolation** - each action only receives the data it needs

### Why We're Changing It

The current implementation has several issues:

| Problem | Impact |
|---------|--------|
| FLeTs handle entity creation AND data storage | Conflates Tier 1 and Tier 2 responsibilities |
| Hardcoded schema flow (Load→Extract→Transform→Save) | Limits composability and reuse |
| Actions coupled by schema types | Can't easily run multiple loads or reuse actions |
| FLeT__Html__To__Cache does too much | Should just save HTML, not manage entities |

### The New Model

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                         NEW ARCHITECTURE LAYERS                              │
└─────────────────────────────────────────────────────────────────────────────┘

    ┌─────────────────────────────────────────────────────────────────────┐
    │                     ORCHESTRATOR LAYER                               │
    │                                                                      │
    │  • Determines cache_key (from URL, explicit, or html-hash)          │
    │  • Computes cache_hash from cache_key                               │
    │  • Creates or retrieves entity (gets cache_id)                      │
    │  • Creates Html_Cache__Document with established cache_id           │
    │  • Calls FLeTs, handles schema transformation between them          │
    │  • Decides which FLeTs to run based on what's already cached        │
    │                                                                      │
    │  RESPONSIBILITY: Entity lifecycle (Tier 1) + FLeT orchestration     │
    └─────────────────────────────────────────────────────────────────────┘
                                    │
                                    │ passes document (with cache_id)
                                    ▼
    ┌─────────────────────────────────────────────────────────────────────┐
    │                         FLeT LAYER                                   │
    │                                                                      │
    │  • Operates WITHIN an already-established entity                    │
    │  • Transforms and stores data to document's data layer              │
    │  • Does NOT create entities                                         │
    │  • Does NOT resolve cache_ids                                       │
    │  • Can have 1 action or many actions                                │
    │                                                                      │
    │  RESPONSIBILITY: Data operations (Tier 2) only                      │
    └─────────────────────────────────────────────────────────────────────┘
                                    │
                                    │ calls
                                    ▼
    ┌─────────────────────────────────────────────────────────────────────┐
    │                        ACTION LAYER                                  │
    │                                                                      │
    │  • Pure functions with uniform signature                            │
    │  • Receives only the data it needs                                  │
    │  • Completely isolated from other actions                           │
    │  • Decorated with @task() for observability                         │
    │                                                                      │
    │  RESPONSIBILITY: Single transformation or I/O operation             │
    └─────────────────────────────────────────────────────────────────────┘
```

## 2. Uniform Action Signatures

### Current Problem

Actions are coupled by schema types:

```python
# Current: Hardcoded schema chain
def load(input_data: Schema__Load__Input) -> Schema__Load__Output:
    ...

def extract(input_data: Schema__Load__Output) -> Schema__Extract__Output:  # ← coupled to load
    ...

def transform(input_data: Schema__Extract__Output) -> Schema__Transform__Output:  # ← coupled to extract
    ...

def save(input_data: Schema__Transform__Output) -> Schema__Save__Output:  # ← coupled to transform
    ...
```

This hardcodes the flow and prevents:
- Running multiple load actions (e.g., load from URL + load from database)
- Reusing actions across different FLeTs
- Skipping phases (e.g., just load and save, no transform)

### New Pattern

Every action has the same conceptual pattern:

```python
# New: Uniform signature pattern
@task()
@type_safe
def action__name(input_data: Schema__Action__Input,
                 document  : Html_Cache__Document = None,    # Optional: for cache operations
                 **dependencies                              # Optional: other dependencies
            ) -> Schema__Action__Output:
    ...
```

**Key principles:**

1. **Each action defines its own input/output schemas** - no coupling to other actions
2. **FLeT's execute() handles schema transformation** - maps outputs to inputs between actions
3. **Actions receive only what they need** - principle of least privilege for data

### Example: Two Load Actions

```python
# action__load_from_url.py
@task()
@type_safe
def action__load_from_url(input_data: Schema__Load_From_Url__Input
                     ) -> Schema__Load_From_Url__Output:
    # Fetch HTML from URL
    return Schema__Load_From_Url__Output(html=fetched_html, source_url=input_data.url)


# action__load_from_file.py
@task()
@type_safe
def action__load_from_file(input_data: Schema__Load_From_File__Input
                      ) -> Schema__Load_From_File__Output:
    # Read HTML from file
    return Schema__Load_From_File__Output(html=file_content, source_path=input_data.path)


# A FLeT could use either or both:
class FLeT__Html__From__Multiple_Sources(Html_FLeT__Base):
    
    def execute(self, input_data):
        # Run both loads
        url_result  = action__load_from_url(Schema__Load_From_Url__Input(url=input_data.url))
        file_result = action__load_from_file(Schema__Load_From_File__Input(path=input_data.path))
        
        # Combine/transform as needed
        combined = self.merge_sources(url_result, file_result)
        
        return combined
```

## 3. Single Responsibility FLeTs

### The L-E-T-S Pattern is a Framework, Not a Mandate

A FLeT can have:

| Pattern | Use Case | Example |
|---------|----------|---------|
| Just **S** (save) | Store data to cache | `FLeT__Html__To__Cache` |
| Just **L** (load) | Retrieve data from cache | `FLeT__Html__From__Cache` |
| **L-T** (load + transform) | Load and transform | `FLeT__Html__To__Dict` |
| **L-E-T-S** (full) | Complex multi-stage pipeline | `FLeT__Url__To__MGraph` |

### FLeT__Html__To__Cache: Simplified

**Current**: Tries to handle entity creation, deduplication, hash computation, AND saving.

**New**: Just saves HTML to an already-established document.

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    FLeT__Html__To__Cache (SIMPLIFIED)                        │
└─────────────────────────────────────────────────────────────────────────────┘

    Input:
    ┌─────────────────────────────────────────┐
    │  document : Html_Cache__Document        │  ← Already has cache_id
    │  html     : Safe_Str__Html              │  ← Content to save
    │  data_key : str = 'html/raw'            │  ← Where to save in data layer
    └─────────────────────────────────────────┘
                        │
                        │ ONE action
                        ▼
    ┌─────────────────────────────────────────┐
    │  action__html_to_cache__save            │
    │                                         │
    │  • Write HTML to document.data_key      │
    │  • Return success/failure + metadata    │
    └─────────────────────────────────────────┘
                        │
                        ▼
    Output:
    ┌─────────────────────────────────────────┐
    │  success   : bool                       │
    │  data_key  : str                        │  ← Where it was saved
    │  char_count: int                        │  ← Metadata
    └─────────────────────────────────────────┘
```

**What moved to Orchestrator:**
- Entity creation/lookup
- cache_key resolution
- cache_hash computation
- Deduplication check (`from_cache`)

## 4. Orchestrator Layer

### Responsibilities

The orchestrator (to be implemented - needs better name than "profiles") handles:

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                        ORCHESTRATOR RESPONSIBILITIES                         │
└─────────────────────────────────────────────────────────────────────────────┘

    1. ENTITY RESOLUTION
       ─────────────────
       • Receive request (URL, HTML, or cache_id)
       • Determine cache_key:
         - Explicit cache_key from request
         - URL as cache_key
         - Derived from html content hash: "html/{html_hash}"
       • Compute cache_hash from cache_key
       • Lookup or create entity → get cache_id

    2. DOCUMENT CREATION
       ─────────────────
       • Create Html_Cache__Document with:
         - cache_id (from step 1)
         - namespace
         - client reference

    3. FLET ORCHESTRATION
       ──────────────────
       • Decide which FLeTs to run based on:
         - What's requested
         - What's already cached
       • Call FLeTs in sequence
       • Handle schema transformation between FLeTs

    4. RESPONSE ASSEMBLY
       ─────────────────
       • Collect results from FLeTs
       • Return combined response with cache metadata
```

### Example Flow: Store HTML from URL

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    ORCHESTRATOR FLOW: URL → Cache                            │
└─────────────────────────────────────────────────────────────────────────────┘

    Request: { url: "https://example.com/page", namespace: "html-cache" }
                        │
                        ▼
    ┌─────────────────────────────────────────────────────────────────────┐
    │  1. ENTITY RESOLUTION                                               │
    │                                                                     │
    │     cache_key  = "https://example.com/page"                        │
    │     cache_hash = hash(cache_key) → "a1b2c3d4..."                   │
    │     cache_id   = lookup_or_create(cache_hash) → "uuid-..."         │
    └─────────────────────────────────────────────────────────────────────┘
                        │
                        ▼
    ┌─────────────────────────────────────────────────────────────────────┐
    │  2. CHECK WHAT'S CACHED                                             │
    │                                                                     │
    │     html_exists = document.data_exists('html/raw')                 │
    │     if html_exists and not force_refresh:                          │
    │         return cached_response                                      │
    └─────────────────────────────────────────────────────────────────────┘
                        │
                        ▼
    ┌─────────────────────────────────────────────────────────────────────┐
    │  3. FETCH HTML (if needed)                                          │
    │                                                                     │
    │     html = FLeT__Html__From__Url.execute(url)                      │
    └─────────────────────────────────────────────────────────────────────┘
                        │
                        ▼
    ┌─────────────────────────────────────────────────────────────────────┐
    │  4. STORE HTML                                                      │
    │                                                                     │
    │     result = FLeT__Html__To__Cache.execute(document, html)         │
    └─────────────────────────────────────────────────────────────────────┘
                        │
                        ▼
    Response: { success: true, cache_id: "uuid-...", from_cache: false }
```

## 5. Simplified Base Classes

### Html_FLeT__Base (Revised)

The base class becomes simpler - just provides Flow/Task execution wrapper and observability:

```python
class Html_FLeT__Base(Type_Safe):
    
    # Configuration
    config   : Schema__FLeT__Config       = None
    document : Html_Cache__Document       = None    # Passed in with cache_id already set
    
    # Execution state (available after execute)
    flow     : Html_FLeT__Flow            = None
    output   : Type_Safe                  = None    # Generic - each FLeT defines its output
    
    def setup(self) -> 'Html_FLeT__Base':
        raise NotImplementedError("Subclasses must implement setup()")
    
    def run_actions(self, input_data: Type_Safe) -> Type_Safe:
        raise NotImplementedError("Subclasses must implement run_actions()")
    
    @type_safe
    def execute(self, input_data: Type_Safe) -> Type_Safe:
        with Html_FLeT__Flow() as flow:
            self.flow     = flow
            flow.document = self.document
            flow.config   = self.config
            
            flow.setup(self.run_actions, input_data)
            flow.execute()
            
            self.output = flow.flow_return_value
            return self.output
    
    # Observability
    def durations(self) -> dict:
        return self.flow.durations() if self.flow else {}
    
    def captured_logs(self) -> list:
        return self.flow.captured_logs() if self.flow else []
```

**Key changes:**
- No mandatory `load`, `extract`, `transform`, `save` methods
- `run_actions()` replaces `run_pipeline()` - name reflects flexibility
- Output type is generic `Type_Safe` - each FLeT specifies its own

## 6. Implementation: FLeT__Html__To__Cache

### Schema

```python
# Schema__Html_To_Cache__Input
class Schema__Html_To_Cache__Input(Type_Safe):
    html     : Safe_Str__Html                      # Content to save
    data_key : Safe_Str__File__Path = 'html/raw'   # Where to save in data layer


# Schema__Html_To_Cache__Output
class Schema__Html_To_Cache__Output(Type_Safe):
    success    : bool                              # Whether save succeeded
    data_key   : Safe_Str__File__Path              # Where it was saved
    char_count : Safe_UInt                         # Content length
```

### Action

```python
# action__html_to_cache__save.py

@task()
@type_safe
def action__html_to_cache__save(input_data: Schema__Html_To_Cache__Input,
                                document  : Html_Cache__Document
                           ) -> Schema__Html_To_Cache__Output:
    
    html_str   = str(input_data.html)
    char_count = len(html_str)
    data_key   = input_data.data_key
    
    # Save to document's data layer
    success = document.data__store_string(data_key = data_key,
                                          content  = html_str )
    
    return Schema__Html_To_Cache__Output(success    = success   ,
                                         data_key   = data_key  ,
                                         char_count = char_count)
```

### FLeT Class

```python
# FLeT__Html__To__Cache.py

class FLeT__Html__To__Cache(Html_FLeT__Base):
    
    def setup(self) -> 'FLeT__Html__To__Cache':
        self.config = Schema__FLeT__Config(
            name        = Safe_Str__FLeT__Name('html-to-cache'),
            description = 'Save HTML content to cache document')
        return self
    
    def run_actions(self, input_data: Schema__Html_To_Cache__Input
               ) -> Schema__Html_To_Cache__Output:
        return action__html_to_cache__save(input_data = input_data    ,
                                           document   = self.document )
    
    @type_safe
    def execute(self, input_data: Schema__Html_To_Cache__Input
           ) -> Schema__Html_To_Cache__Output:
        return super().execute(input_data=input_data)
```

**That's it.** One action. One responsibility. Clean and simple.

## 7. Implementation: FLeT__Html__From__Cache

Following the same pattern:

### Schema

```python
# Schema__Html_From_Cache__Input
class Schema__Html_From_Cache__Input(Type_Safe):
    data_key : Safe_Str__File__Path = 'html/raw'   # Where to load from


# Schema__Html_From_Cache__Output  
class Schema__Html_From_Cache__Output(Type_Safe):
    success : bool                                 # Whether load succeeded
    html    : Safe_Str__Html                       # Retrieved content
    found   : bool                                 # Whether data existed
```

### Action

```python
@task()
@type_safe
def action__html_from_cache__load(input_data: Schema__Html_From_Cache__Input,
                                  document  : Html_Cache__Document
                             ) -> Schema__Html_From_Cache__Output:
    
    data_key = input_data.data_key
    
    # Check if exists
    if not document.data__exists(data_key=data_key):
        return Schema__Html_From_Cache__Output(success = False,
                                               html    = ''   ,
                                               found   = False)
    
    # Load from document's data layer
    html_str = document.data__retrieve_string(data_key=data_key)
    
    return Schema__Html_From_Cache__Output(success = True                   ,
                                           html    = Safe_Str__Html(html_str),
                                           found   = True                    )
```

### FLeT Class

```python
class FLeT__Html__From__Cache(Html_FLeT__Base):
    
    def setup(self) -> 'FLeT__Html__From__Cache':
        self.config = Schema__FLeT__Config(
            name        = Safe_Str__FLeT__Name('html-from-cache'),
            description = 'Load HTML content from cache document')
        return self
    
    def run_actions(self, input_data: Schema__Html_From_Cache__Input
               ) -> Schema__Html_From_Cache__Output:
        return action__html_from_cache__load(input_data = input_data    ,
                                             document   = self.document )
```

## 8. Test Strategy

### Testing FLeTs in Isolation

FLeTs can now be tested with a pre-created document:

```python
class test_FLeT__Html__To__Cache(TestCase):
    
    @classmethod
    def setUpClass(cls):
        # Create in-memory cache and document
        cls.cache_client, cls.cache_service = create_html_cache_client()
        cls.document = create_test_document(cache_client = cls.cache_client,
                                            namespace    = 'test-ns'       ,
                                            cache_key    = 'test/entity'   )
    
    def test_execute__saves_html(self):
        flet       = FLeT__Html__To__Cache(document=self.document).setup()
        input_data = Schema__Html_To_Cache__Input(html='<p>Test</p>')
        
        result = flet.execute(input_data)
        
        assert result.success    is True
        assert result.data_key   == 'html/raw'
        assert result.char_count == 11
    
    def test_round_trip(self):
        # Save
        save_flet = FLeT__Html__To__Cache(document=self.document).setup()
        save_flet.execute(Schema__Html_To_Cache__Input(html='<p>Round trip</p>'))
        
        # Load
        load_flet = FLeT__Html__From__Cache(document=self.document).setup()
        result    = load_flet.execute(Schema__Html_From_Cache__Input())
        
        assert result.found       is True
        assert str(result.html)   == '<p>Round trip</p>'
```

### Testing Orchestrator

Orchestrator tests verify entity management and FLeT coordination:

```python
class test_Html_Cache__Orchestrator(TestCase):
    
    def test_store_html_from_url(self):
        result = orchestrator.store_html(url       = 'https://example.com/page',
                                         namespace = 'test-ns'                 )
        
        assert result.success  is True
        assert result.cache_id is not None
    
    def test_deduplication(self):
        # Store same URL twice
        result1 = orchestrator.store_html(url='https://example.com/page', namespace='test-ns')
        result2 = orchestrator.store_html(url='https://example.com/page', namespace='test-ns')
        
        # Same entity
        assert result1.cache_id == result2.cache_id
        assert result2.from_cache is True
```

## 9. Summary

### Before vs After

| Aspect | Before | After |
|--------|--------|-------|
| Entity management | Inside FLeT | Orchestrator layer |
| Action coupling | Schema chain (L→E→T→S) | Independent, uniform signatures |
| FLeT complexity | Must implement 4 phases | Can have 1 action |
| Schema flow | Hardcoded | Orchestrator handles mapping |
| Deduplication | Inside FLeT__Html__To__Cache | Orchestrator checks before calling FLeT |
| Data isolation | Actions see full pipeline data | Actions see only what they need |

### Key Principles

1. **Orchestrator handles Tier 1** (entity lifecycle)
2. **FLeTs handle Tier 2** (data operations within entity)
3. **Actions are atoms** - pure functions, uniform interface
4. **FLeTs compose actions** - can be as simple as one action
5. **Single responsibility** - each layer does one thing well

3. Implement `FLeT__Html__From__Cache` with single action
