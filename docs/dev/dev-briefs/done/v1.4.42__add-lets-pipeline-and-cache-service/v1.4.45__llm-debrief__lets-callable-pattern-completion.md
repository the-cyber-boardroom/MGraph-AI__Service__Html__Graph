## 1. Callable Pattern Analysis: IDE Support vs Runtime Safety

### The Problem

The new `Html_LETS__Base` uses class-level `Callable` attributes instead of abstract methods:

```python
# New pattern (loses IDE completion)
load      : Callable = None
extract   : Callable = None
transform : Callable = None
save      : Callable = None
```

vs the old pattern:

```python
# Old pattern (has IDE completion + NotImplementedError)
def load(self, input_data):
    raise NotImplementedError()
```

### Tradeoffs Discussed

| Approach | IDE Completion | Compile-time Safety | Declarative Wiring |
|----------|---------------|---------------------|-------------------|
| Abstract methods | ✅ Full | ✅ NotImplementedError | ❌ Override syntax |
| `Callable = None` | ❌ None | ❌ TypeError on None | ✅ Clean assignment |
| `Callable[[In], Out]` | ⚠️ Partial | ❌ TypeError on None | ✅ Clean assignment |
| Hybrid (delegate) | ✅ Full | ✅ Custom error | ⚠️ More boilerplate |

### Solution Adopted

Used typed `Callable` with full signatures for better IDE hints:

```python
load      : Callable[[Schema__LETS__Load__Input      ], Schema__LETS__Load__Output     ] = None
extract   : Callable[[Schema__LETS__Load__Output     ], Schema__LETS__Extract__Output  ] = None
transform : Callable[[Schema__LETS__Extract__Output  ], Schema__LETS__Transform__Output] = None
save      : Callable[[Schema__LETS__Transform__Output], Schema__LETS__Save__Output     ] = None
```

Runtime safety provided by `validate_actions()` which runs before `execute()`.

## 2. Html_LETS__Base Test Alignment

### Problem

Original tests expected `NotImplementedError` from calling action methods:

```python
def test_load__raises_not_implemented(self):
    with Html_LETS__Base() as _:
        with self.assertRaises(NotImplementedError):
            _.load(load_input=None)  # Now raises TypeError, not NotImplementedError
```

### Solution

Rewrote tests to validate the new Callable pattern:

```python
# Test actions start as None
def test__init____actions_are_none(self):
    with Html_LETS__Base() as _:
        assert _.load      is None
        assert _.extract   is None
        assert _.transform is None
        assert _.save      is None

# Test validation catches missing actions
def test_validate_actions__all_missing(self):
    with Html_LETS__Base() as _:
        with self.assertRaises(ValueError) as context:
            _.validate_actions()
        assert 'missing actions' in str(context.exception).lower()

# Test validation passes when wired
def test_validate_actions__all_wired(self):
    with Html_LETS__Base() as _:
        _.load      = lambda x: x
        _.extract   = lambda x: x
        _.transform = lambda x: x
        _.save      = lambda x: x
        _.validate_actions()  # Should not raise
```

### New Test Coverage

| Test | Purpose |
|------|---------|
| `test__init____actions_are_none` | Verify actions start unbound |
| `test__init____document_is_none` | Verify document not set |

| `test__init____output_is_none` | Verify output not set |

## 3. Html_LETS__Executor Refactoring

### Critical Bug Identified

The executor was **bypassing the Flow/Task system entirely**:

```python
# OLD (BROKEN) - Direct method calls, no Flow observability
def execute_single(self, ...):
    load_output      = lets_instance.load(context)        # Direct call
    extract_output   = lets_instance.extract(load_output) # Direct call
    transform_output = lets_instance.transform(extract_output)
    save_output      = lets_instance.save(transform_output)
```

This completely defeated the purpose of the Flow/Task refactor - no timing, no logging, no observability.

### Solution

Refactored to use `execute()` method which invokes the Flow system:

```python
# NEW (CORRECT) - Uses Flow/Task system
def execute_single(self, ...):
    lets_instance = lets_class(document=self.document)  # Pass document
    lets_instance.setup()
    
    try:
        load_input  = Schema__LETS__Load__Input(html=context.html)
        save_output = lets_instance.execute(load_input)  # Uses Flow!
        success     = save_output.success
    except Exception as e:
        # Error handling...
```

### Key Changes

1. **Document propagation**: `lets_class(document=self.document)` passes cache document to step
2. **Proper input conversion**: Creates `Schema__LETS__Load__Input` from context
3. **Uses `execute()`**: Invokes Flow system for observability
4. **Maintains caching**: Still checks/updates cache when document available

### Test Updates

Removed test that depended on unrefactored step:

```python
# REMOVED - Would fail until Html_LETS__Html__To__Dict refactored
def test_execute_pipeline__single_lets(self):
    results = _.execute_pipeline(lets_classes=[Html_LETS__Html__To__Dict], ...)
```

## 4. Enum__Html_LETS__Type Review

### Assessment: Keep As-Is

The enum pattern is well-designed and valuable:

```python
class Enum__Html_LETS__Type(Enum):
    HTML_FROM_RAW  = Html_LETS__Html__From__Raw
    HTML_TO_DICT   = Html_LETS__Html__To__Dict
    DICT_TO_MGRAPH = Html_LETS__Dict__To__MGraph
```

### Why It's Good

1. **Type-safe lookup**: `Enum__Html_LETS__Type['HTML_TO_DICT'].value` returns class
2. **Pipeline building**: Easy to construct pipelines from config
3. **Auto-conversion**: Works with `@type_safe` string→enum conversion
4. **Validation**: Only registered LETS types can be used

### Test Adjustments

Minor changes to use refactored step (`Html_LETS__Html__From__Raw`) in tests:

```python
def test_instantiate_and_setup(self):
    lets_class = Enum__Html_LETS__Type.HTML_FROM_RAW.value  # Use refactored one
    instance   = lets_class().setup()
    assert instance.config.name == 'html-from-raw'
```

## 5. Html_LETS__Dict__To__MGraph Migration

### Before: Method-Based Pattern

```python
class Html_LETS__Dict__To__MGraph(Html_LETS__Base):
    @type_safe
    def load(self, load_input: Schema__Dict_To_MGraph__Load__Input):
        return Schema__Dict_To_MGraph__Load__Output(html_dict=load_input.html_dict)
    
    @type_safe
    def transform(self, transform_input: Schema__Dict_To_MGraph__Transform__Input):
        mgraph_data = self.build_mgraph(transform_input.html_dict)
        return Schema__Dict_To_MGraph__Transform__Output(...)
    
    # Missing extract() - would fail validation
```

### After: Declarative Callable Pattern

```python
# Module-level action functions
@task()
@type_safe
def action__dict_to_mgraph__load(input_data: Schema__Dict_To_MGraph__Load__Input
                            ) -> Schema__Dict_To_MGraph__Load__Output:
    return Schema__Dict_To_MGraph__Load__Output(html_dict=input_data.html_dict)

@task()
@type_safe
def action__dict_to_mgraph__extract(input_data: Schema__Dict_To_MGraph__Load__Output
                               ) -> Schema__Dict_To_MGraph__Extract__Output:
    return Schema__Dict_To_MGraph__Extract__Output(html_dict=input_data.html_dict)

@task()
@type_safe
def action__dict_to_mgraph__transform(input_data: Schema__Dict_To_MGraph__Extract__Output
                                 ) -> Schema__Dict_To_MGraph__Transform__Output:
    mgraph_data = build_mgraph(input_data.html_dict)
    return Schema__Dict_To_MGraph__Transform__Output(...)

@task()
@type_safe
def action__dict_to_mgraph__save(input_data: Schema__Dict_To_MGraph__Transform__Output
                            ) -> Schema__LETS__Save__Output:
    return Schema__LETS__Save__Output(success=True)

# Helper as module function
def build_mgraph(html_dict: Schema__Html_Dict) -> Dict[str, Any]:
    if html_dict is None:
        return {'graph': {'nodes': [], 'edges': []}, 'source': {}}
    return {'graph': {'nodes': [], 'edges': []}, 'source': html_dict.html_dict}

# Declarative class wiring
class Html_LETS__Dict__To__MGraph(Html_LETS__Base):
    load      = action__dict_to_mgraph__load
    extract   = action__dict_to_mgraph__extract
    transform = action__dict_to_mgraph__transform
    save      = action__dict_to_mgraph__save
    
    def setup(self) -> 'Html_LETS__Dict__To__MGraph':
        self.config = Schema__LETS__Config(name='dict-to-mgraph', ...)
        return self
```

### Key Changes

1. **Added missing `extract` action** - Original was missing, would fail validation
2. **Made `build_mgraph` module-level** - Easier to test, cleaner separation
3. **Added `None` handling** - `build_mgraph(None)` returns empty structure
4. **All actions `@task()` decorated** - Flow system tracks execution

### Test Changes

```python
# OLD - Manual L-E-T-S calls
def test_integration__full_pipeline(self):
    load_output      = _.load(load_input)
    transform_output = _.transform(Schema__Transform__Input(html_dict=load_output.html_dict))
    save_output      = _.save(Schema__Save__Input(mgraph_document=...))

# NEW - Use execute() method
def test_execute__simple(self):
    step       = Html_LETS__Dict__To__MGraph().setup()
    input_data = Schema__Dict_To_MGraph__Load__Input(html_dict=self.sample_html_dict)
    result     = step.execute(input_data)
    assert result.success is True
```

## 9. Architectural Insights

### Pattern Consistency

All LETS steps now follow the same structure:

```python
# 1. Module-level schemas
class Schema__Step__Load__Input(Schema__LETS__Load__Input): ...
class Schema__Step__Load__Output(Schema__LETS__Load__Output): ...
class Schema__Step__Extract__Output(Schema__LETS__Extract__Output): ...
class Schema__Step__Transform__Output(Schema__LETS__Transform__Output): ...

# 2. Module-level action functions
@task()
@type_safe
def action__step__load(input_data): ...

@task()
@type_safe
def action__step__extract(input_data): ...

@task()
@type_safe
def action__step__transform(input_data): ...

@task()
@type_safe
def action__step__save(input_data): ...

# 3. Declarative class wiring
class Html_LETS__Step(Html_LETS__Base):
    load      = action__step__load
    extract   = action__step__extract
    transform = action__step__transform
    save      = action__step__save
    
    def setup(self): ...
```

### Benefits Realized

1. **Composability**: Actions can be mixed across steps
2. **Testability**: Test functions in isolation or via execute()
3. **Observability**: Flow tracks all action timings/logs
4. **Type Safety**: Full Callable signatures enable IDE hints
5. **Validation**: `validate_actions()` catches wiring errors at runtime

## 10. Key Decisions

| Decision | Rationale |
|----------|-----------|
| Typed Callable over abstract | Better IDE support while keeping declarative pattern |
| Runtime validation over compile-time | `validate_actions()` catches errors before execute |
| Module-level actions | Enables reuse, composition, and isolated testing |
| Helper functions as module-level | Cleaner separation, easier testing |
| Keep Enum pattern | Provides type-safe lookup and pipeline building |
